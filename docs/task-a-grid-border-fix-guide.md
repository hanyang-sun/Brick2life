# 顶视预览底部横线修复

2026-10-16。

## 原因与结果

原始 512×512 相机图像仍有底部横线。缩小显示时，线条边缘会与底板、背景混合；四条外框原先和内部格线同为 0.04，部分采样位置下会接近背景色，看起来像消失。

现在内部格线保持 0.04，四条外框使用 0.08。线段中心和端点仍在原来的 X/Z=0～10，格长、相机、纹理尺寸和积木坐标都不需要调整。实际 RGB 中的外框会加粗，因此修复后的 RGB 与修复前不同，这是本次预期变化。

## 新代码如何工作

`lineWidth` 控制内部格线宽度；新增的 `borderWidth` 控制外框宽度。它们的单位都是 Unity 世界单位，不是屏幕像素。

循环 `i=0～10` 中，每次创建一条沿 X 方向和一条沿 Z 方向的线。只有 `i==0` 或 `i==10` 时，两条线才位于棋盘四周；此时用 `Mathf.Max(lineWidth, borderWidth)`，保证外框至少与内部线一样宽。其余 18 条内部线沿用原宽度。

生成后的 `xLine` 和 `zLine` 分别把 `widthMultiplier` 设置为本次选定的 `currentWidth`。原有的 `SetPosition` 坐标保持原值。

## 验证与范围

在当前主工程的 Unity 6000.3.24f1 中，用真正的 `Camera.Render` 和 GPU `Graphics.Blit` 检查 512、384、280、256 四种尺寸，以及四种亚像素位置。测试取右侧没有积木遮挡的区域，不把积木挡住的底边算作丢线。

32 项顶底边检查中，修复前有 14 项不能保留明确的深色行；外框加粗试验、脚本修复后重新进入 Play，均为 32/32 通过。三种 Game 尺寸 553×721、1024×768、1280×720 的格位拾取检查各 114 项通过，且修复后固定相机 RGB 的 SHA256 一致。

这是对上述尺寸和采样位置的验证，不代表任意小的预览都能完整保留全部细格线。检查针对网格外框修复，没有完成新增、删除、移动或图像识别。
