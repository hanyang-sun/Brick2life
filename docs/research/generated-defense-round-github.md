# 自动核心、随机多入口与堵路沿用旧路线：GitHub 检索

日期：2026-10-30。本文在本轮生产代码编写前完成，依据用户已确认的新玩法，替代此前由玩家放置核心和手选入口、堵路暂停推进的默认规则。

## 范围与验收依据

- 每局由系统生成一个固定核心和一个或多个出生点；数量不写死为一。生成结果须能记录种子及实际坐标，便于复现实验。
- 玩家只摆城墙与防御塔，暂不设额外数量配额，仍受棋盘空位与一格一块的约束。准备阶段、战斗中都允许增删和移动。
- 核心与出生点属于系统目标，不是由 B 猜出的蓝色积木，也不由玩家删除或移动。B 仍只根据 RGB 预测玩家积木，Ground Truth 仅用于评价。
- 新布局堵路时显示提示，敌人继续最后一份有效路线，不暂停、不回到入口、不重置本局进度。允许旧路线穿过刚放置的障碍是这条用户规则的结果，显示时需要明确说明；不能偷偷把新墙删除或把识别结果回滚。

本轮先复核 README、架构说明与现有 [实时改图研究记录](live-battle-editing-github.md)，再检索 GitHub。关键词：`GameBoard FindPaths SpawnPoint`、`Unity tower defense random spawn destination`、`RecalculateWalkableNodes`。下列候选源码与 README 已实际阅读，并检查许可证。

## 具体适配方案

1. 新增 Unity-free 的回合配置，拥有棋盘定义、种子、固定核心、入口集合与保留格查询。初始在无玩家障碍的棋盘上生成目标，保证核心与入口互不重合、入口唯一且都有初始通路。生成配置可限制入口在边缘、核心在内侧。记录种子、生成参数和实际坐标，避免把跨版本随机数实现当成复现保证。
2. 系统核心与出生点单独生成、显示和保护。角色映射只将 RGB 确认的玩家积木映射为墙/塔；应用层把已知关卡目标合入游戏状态，不把目标位置写回 B 的观测或伪造识别结果。目标显示分层需确保不会被顶置相机当作玩家积木拍到。
3. 每次 B 确认布局后，继续复用现有 BattleLevel/RouteSearch 生成候选路线。正常情况按已有连续位置重规划，保留敌人 ID、血量、位置、波次、计时、核心生命及用户暂停状态。
4. 新玩法启用“保留最后有效路线”策略：路径失败与状态错误分别报告，路径失败时保留旧路线并继续移动和出怪；新的塔与确认地图仍可更新。多入口必须保持原索引与入口坐标的对应，不能把部分成功的候选路径压缩后套到错误入口。
5. 第一版可以原子采用最后有效的整组入口路线，避免部分更新造成编号混乱；之后若需要逐入口回退，再单独设计。成功重新规划后清除警告。出生点和核心在本局固定，不能在回退时隐式改变。
6. UI 显示系统目标、当前入口数量、种子/重生成入口、墙塔数量不限的规则，以及“堵路，沿用上次有效路线”的状态。新的规则不影响原双窗口只读展示与编辑焦点限制。

## 验证计划与边界

- 回合生成：固定种子重复一致、一个核心、1/2/多个入口、互异且在范围内、核心与入口不重合、边界输入被拒绝、初始地图均可寻路。不同种子无需保证绝无碰撞，但应覆盖多种布局。
- 玩家操作：不能在目标保留格放置或移入积木，不能删除/拖动系统目标；墙塔不额外限额，清空只影响玩家积木。识别仍经过真实 RGB 和稳定确认，真值仅用于评分。
- 旧路回退：封死某入口、封死所有入口、在敌人脚下建墙、频繁改图；确认战斗时钟/出怪继续，原敌人不瞬移，后续敌人仍用对应入口有效旧路，手动暂停仍生效。移除阻碍后成功更新并清除警告。
- 动态塔：即使候选路线被拒绝，移除的塔停止开火、新增塔按规则加入，避免误把整个旧地图回滚。
- 显示与图像隔离：准备阶段即可看见系统目标；原始和投影展示都对应同一回合；顶置 RGB 不包含系统目标模型；仍验证投影开关、独立展示渲染前后源 RGB 不变。
- 本轮只覆盖固定 10×10 单层仿真。运行时基础规则保持离线、Unity-free，新的显示入口依旧以 Unity 6000.3 编辑器场景验证；Android、真实投影设备和多层不在已验证范围。

## 实施结果

已按上述机制扩展自有模块，没有引入外部代码或依赖。生成算法复用仓库 DatasetPlan 的确定性 xorshift 思路，入口寻路继续使用自有四方向 A*。默认每局 1 个内侧核心、1–4 个边缘入口，系统目标与 B 积木占用分离，堵路仅保留路线而不回滚新墙塔。

纯 C# 1076 项、Unity 新玩法真实 RGB 场景 167 项、原双窗口 179 项、控制器 131 项、实时编辑 71 项通过。新场景中目标提示开关和预览前后的源 RGB 变化都为 0 像素，干净样例整盘精确识别率 100%。联调还修复了清除投影时旧面片延迟一帧可见、展示窗口重复镜像系统提示、重试后准备路线不恢复的问题。复核补上了“墙压住敌人、敌人离开后同一确认布局自动恢复规划”的检查，先复现失败，再修正为按模拟时间间隔重试。当前受伤反馈也贴合系统核心的桌面高度。

操作、文件调用链和未验证边界见 [实现指南](../generated-defense-round-guide.md)。这些验证不替代真实投影干扰实验、关卡平衡或多层验收，本轮未重新构建 Windows Player。
