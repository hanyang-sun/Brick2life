# 透视相机与底板反馈的可行性审查

检索日期：2026-10-19。范围：仅判断纯 Unity 单层 RGB 识别→游戏→投影路线是否适合当前项目；本轮不实现功能，不表示真实相机已经标定。关键词：Unity 6000.3 Physical Camera、Built-in post processing、OpenCV planar homography、camera calibration distortion。

## 结论与证据边界

方向可行，适合把理想功能演示推进为可重复的几何与抗干扰实验。保留正交模式作对照，先实现透视成像、单层识别、暴露底板反馈闭环，再分别加入畸变、曝光变化和投影干扰。纯仿真能够验证选定模型下的行为与误差，不能据此声称真实设备可靠；真实镜头参数、噪声和投影表面仍需真机采集与独立验证。

Unity 6000.3 的物理相机支持以焦距、传感器尺寸等控制透视成像，因此第一步不必迁移渲染管线或增加外部库。该功能不等于已经模拟镜头畸变、自动曝光或真实传感器。[Unity Physical Cameras](https://docs.unity3d.com/6000.3/Documentation/Manual/PhysicalCameras.html)

## 两个平面与两段标定

平面单应矩阵依赖共面假设。底板 y=0、单位积木顶面 y=1 是两个平面；透视下不能普遍共用底板 H。相机位于 (5,12,5)、竖直俯视时，顶面点按底板反算的单轴误差为距光轴水平距离×1/(12−1)；若距离为 4.5，约为 0.409 格。这只是理想几何估算，不是实测结果。[OpenCV homography 理论与示例](https://docs.opencv.org/4.13.0/d9/dab/tutorial_homography.html)

限制反馈为暴露底板是可行首阶段，可将 C 的落点目标限制在单一平面，但 B 识别顶面仍须使用独立的顶面 H，或公开内外参 K/R/t 后与已知顶面求交。不能用真实积木占用替代 B 的 RGB 识别输入。相机图像→棋盘平面和棋盘平面→投影仪图像是不同的两段标定；若 C 直接借用 Unity 几何准确渲染，应将其表述为仿真投影，不冒充已测得投影仪标定。

## 分阶段验收

1. 透视几何：固定相机参数与采集分辨率，先保持无畸变。分别记录底板、顶面映射；留出分布在中心、边缘和角部的测试点，不参与求 H。误差从 RGB 中检测的标记或实际渲染落点测量，报告像素误差与换算后的格距误差、均值/最大值，并明确失败点；避免仅用同一 Unity 矩阵正反算自验。
2. 底板反馈：由 B 的预测决定暴露区域，检查反馈不落入预测占用格；GT 仅用于评测。投影开启后再次采集，验证 RGB→识别→游戏→投影闭环，分别记录识别准确率、落点误差和延迟。
3. 畸变：加入可控径向/切向参数，明确图像畸变方向和参数约定。Brown–Conrady 一类模型含径向与切向项，不能由单个 H 普遍吸收；先去畸变再做平面映射。测试参数属于合成条件，不称为真实镜头标定。[OpenCV Camera Calibration](https://docs.opencv.org/4.13.0/dc/dbb/tutorial_py_calibration.html)
4. 曝光与投影干扰：单独改变亮度、裁剪/饱和及反馈图案，再做组合实验，避免把颜色误识别归因于几何标定。Built-in 默认没有内置后处理链，官方支持另装 Post Processing v2；因此该阶段需比较简单图像处理与后处理包的依赖成本，先不引入新依赖。[Unity Post-processing overview](https://docs.unity3d.com/6000.3/Documentation/Manual/PostProcessingOverview.html)
