# v1.3：先校对实物，再设计游戏布局

日期：2026-10-12。用户同意统一在地图校对环节核验积木识别和网格位置恢复正确率。本文件扩展 v1.2 的照片确认流程，拍摄条件仍采用无格纸、单层、等大立方体、近俯拍。

## 用户流程

1. 取色、分析照片，进入可编辑草稿。原始拒绝状态不阻止人工校对；未知、裁切、拆分失败等诊断保留，可用检测不被清空。
2. 对照原照片校对数量、颜色、相对格位；选择后点空格移动，添加/改色、删除、整体按格平移，撤销最近 64 次可撤销修改或恢复原始结果。
3. 勾选逐块核验，确认实物布局，冻结人工真值与两项统计。不要求核心或道路，要求非空、颜色已映射、格位在 10×10 范围内且不重叠。
4. 自由设计游戏布局。可以增删、改角色或移动整体，统计和真值保持不变；三维预览复用正交视图并支持现有鼠标/触摸旋转缩放。
5. 发布要求有核心且格位合同完整。无路地图仍可预览，再选择出生点；战斗启动要求全部已选入口有效可达。

“返回照片”保留当前会话草稿；同一个分析结果再次进入时继续编辑。换图、改标定并重新分析后创建新会话。取消或发布失败不覆盖现有关卡。

## 人工真值与指标

- 稳定 ID 对应同一个实物。移动和改色保留 ID；删除原检测表示误检，补加新 ID 表示漏检。修正同一块请移动/改色，避免用删除再补加表示移动。
- 识别正确率：真值中与原始检测 ID 匹配且颜色一致的块数 / 真值总块数。
- 网格位置恢复正确率：真值中与原始检测 ID 匹配且相对行列一致的块数 / 真值总块数，与颜色是否正确无关。
- 相对坐标约定在计算前固定：原始与真值各自使用最小列、最小行归一到 1；不根据真值寻找任意最佳平移或旋转。整体平移不改变相对位置。漏检边缘块导致其他相对格位变化也会反映在位置统计中。
- 分别保存漏检、误检、颜色错误、已匹配块位置错误。原始扫描拒绝状态保留；逐次人工校对记录不代表总体识别率或正式集验收。
- 自由设计不参与这两项计算；返回重新校对后必须再次确认。实物为空的样本不在此交互指标分母中，由异常测试另评估。

## 数据与模块

Contracts：LayoutReviewModels 定义阶段、统计和快照记录。Application：LayoutEditSession 负责身份、编辑、撤销、真值和比较，PhotoScanSession.BeginReview 使用分析时冻结的颜色规则。

Presentation：LayoutReviewPanel 提供原照片、二维点选草稿、列表、工具、阶段确认与三维预览。预览独立于 LevelSession.Current；发布经原有 TryLoad 更新。

Infrastructure：LayoutReviewStore 以临时文件加替换写入 `Scans/<scanId>/review-<reviewId>.json`，保留原扫描记录。确认时保存 published=false，发布成功后更新 published=true。保存出错保留会话供重试。

报告含 schemaVersion、坐标约定、原始状态、确认时间、原始/真值/设计三组积木及像素证据、统计、阶段编辑记录。设计后的布局不使用原照片 BoardToImage 作为投影关系，原投影仍保存在扫描报告。
