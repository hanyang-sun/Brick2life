# v1.2：照片识别仅保留无格纸模式

日期：2026-10-11。用户实拍有格纸流程三四次未成功，要求删除。本文取代 v1 的格纸拍摄、标记定位要求，以及 v1.1 的双模式入口要求；其余格位映射、颜色角色、寻路与战斗规则按现有规格执行。

## 当前流程

导入 PNG/JPG 或相机拍照 → 背景与三角色颜色标定 → 检测独立积木 → 相对 10×10 网格核对 → 确认关卡 → 20×20 导航格 → 选择多个出生点 → 战斗。

- 扫描页直接使用无格纸检测，不提供输入模式切换或格纸导出。
- 拍摄使用干净、与积木可区分的背景；同尺寸立方体、单层、近似正上方拍摄，全部积木完整入镜，并至少有一块可见的独立方块用于尺寸估计。
- 用户采样背景、核心、城墙和防御塔颜色。仍只有三种游戏角色，颜色值不硬编码；标定保存在既有 `BrickDefense.PhotoCalibration.plain.v1` 四颜色数组中。
- 按检测边长估算相对间距和格位，图像左上方向为参考；保留逐块像素证据、数量、颜色与拒绝原因。
- 扫描报告继续写 `inputMode=PlainBackground`、`coordinateBasis=RelativeBrickScale`、`boardIsReliable=false`，表示未恢复固定物理原点或实际高度。
- 未知颜色、裁切、几何拆分不可靠、格位冲突或超界时拒绝；失败扫描不覆盖现有地图。成功且包含核心后才允许生成关卡。

## 验收与范围

实际验证默认入口、已保存标定恢复、取色/保存、完整照片识别、核对/确认、裁切拒绝、当前地图保留与宽窄屏操作。基准实拍样本为 `Tests/Fixtures/real-unmarked-bricks-v1.jpg`，人工标注 7 橙、2 蓝、1 白，共 10 块；它们的角色由本次标定决定。

历史格纸检索、实验文档与原图继续用于追溯，当前程序不再执行其识别、投影或标记代码。本次流程裁剪没有提升通用实拍准确率的实测结论；堆叠、明显斜拍、遮挡、复杂背景和 Android 真机验收仍需后续工作。
