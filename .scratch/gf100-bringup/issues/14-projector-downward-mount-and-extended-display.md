# 14 投影朝下安装、散热与 Windows 独立扩展显示器

规格见 [spec](../spec.md)。

## 问题

需求文档 02 节对投影仪有三条与"安装"有关的硬要求：

1. 具备 HDMI 输入，**能被 Windows 识别为独立扩展显示器**（不是投屏接收器）；
2. **镜头可垂直向下固定并连续工作**；
3. 机身有匹配的安装方式与**散热空间**；「普通吊装菜单和云台角度需结合厂家的安装说明核验」。

红米 3 Lite 已知：**桌上正投 / 吊装正投**、1080p、有手动对焦与手动四点梯形。它是**云台机型**（可俯转），这一点对本项目有利——相机与投影都要朝下。

## 两个方向的风险

| 方案 | 风险 |
|---|---|
| **云台俯转 90° 朝下**（推荐） | 机身仍正立散热，风险小；但俯转后**自动梯形/无感全向自动校正会重新动作**，必须切到手动四点梯形并锁死 |
| **整机倒挂** | 风扇吸风口朝向可能违反厂家散热设计；需要吊架；重力方向变化可能影响光机/色轮（如为 DLP） |

## 待做

### 0. 先确认 HDMI 口是"输入"而不是输出/ARC

部分微型投影把 HDMI 标在参数里，实际是 **ARC 或输出**。同时确认输入能否协商到 **1920×1080@60**（原生 1080p 面板不代表输入接受 1080p；有的只吃 720p 再放大）。

> 这一条直接决定 issue 25 的每格像素：1080p 输入 → 72 px/格；720p 输入 → 43 px/格。

### 0b. 智能系统叠加层必须能关干净（Android 机型专属风险）

这类机型是 Android 智能投影，**HDMI 输入时系统仍可能叠加**：音量条、信号源提示、屏保、休眠/自动关机、系统更新弹窗、广告位。

这会破坏本项目的核心假设：`CellProjection` 记录的是 **Unity 渲染出的 command**，`TryRecover` 反解时假设"投出的就是我算的那一帧"。任何系统叠加都会让实际投影内容与 command 不符 → 反解错误；叠加物还会改变局部亮度，等同于空间不均匀。

**必须确认**：
- 能关闭屏保、休眠、无操作自动关机；
- 能关闭所有系统提示/弹窗/广告位；
- HDMI 输入时系统 UI 不会弹出；
- 优选有"开机直进 HDMI"或"显示器模式"的选项；
- **不能有"输入无信号自动切回安卓桌面"** —— 一掉信号识别就中断。

### 1. 朝下安装与连续运行
   - 记录机身各面温度（手感 + 红外测温）；
   - 观察是否出现**亮度衰减、降频、自动关机、画面偏色**。
2. **Windows 识别**：`Win + P` 选「扩展」，确认设置 → 系统 → 显示里出现**两个显示器**；确认第二屏能到 **1920×1080@60**。
3. 确认**自动功能全部关闭**（与 issue 04 联动）：自动梯形、无感全向自动校正、自动对焦 → 改为手动四点梯形 + 手动对焦。
4. 记录投影仪**进出风口位置**，确认朝下姿态下不被托板/支架遮挡；插头周围按说明书留空。

## 判据

- 连续 2 小时无降亮度/停机；
- Windows 侧稳定识别为独立第二显示器，分辨率 1920×1080@60，不退回 1024×768；
- 手动校正后**画面不再自己变**（静置 10 分钟观察角点是否漂移）。
