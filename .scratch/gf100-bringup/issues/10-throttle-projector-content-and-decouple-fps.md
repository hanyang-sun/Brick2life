# 10 投影内容更新节流，且相机帧率与投影不锁相

规格见 [spec](../spec.md)。

## 问题

卷帘快门下，一帧的读出跨度约等于投影帧周期。若投影画面每帧都在变，几乎**每一帧**都会落在"内容变过"的窗口里。

稳定帧占比近似：

```
1 − (T_readout + T_row) / T_内容更新周期
```

| 投影内容更新率 | 更新周期 | 卷帘下预期稳定帧占比 |
|---|---|---|
| 60 Hz（每帧刷） | 16.7 ms | **≈ 0%** |
| 30 Hz | 33.3 ms | ≈ 50% |
| 15 Hz | 66.7 ms | ≈ 75% |
| 只在布局变化时更新 | 秒级 | ≈ 100% |

另外还有一个更隐蔽的问题：**若相机帧率与投影刷新率锁相**（例如相机 60 fps ↔ 投影 60 Hz），错位方式每帧固定不变，"上半是 A、下半是 B"会稳定复现，于是连续 3 帧互相一致 → issue 07 想加的签名校验如果只比 command 值也抓不住（错法相同）。反过来，让两者**不锁相**（相机 25 或 30 fps ↔ 投影 60 Hz），错位方式逐帧变化，3 帧规则与签名校验才真正有效。

## 待做

1. **投影内容节流**：新增一层"送给投影的画面只在必要时更新"的节流，目标 **≤ 15 Hz**（第一阶段用 10–15 Hz 更稳）。
   - Unity 内部仍可按 60 Hz 渲染与插值做动画；
   - 但**实际下发到投影的渲染结果**只在节流周期变化。
2. **相机帧率与投影不锁相**：请求 25 或 30 fps，**不要 60**。在 `RecognitionSamplingCadence`（已有 `StableInterval` / `ConfirmationInterval`）的框架里体现。
3. 与 issue 08 联动：节流后应能在 `StableDuringExposure` 上看到明显的真值率提升，用 issue 09 的计数验证。

## 注意

节流会改变"人眼看投影"的观感。若游戏反馈需要连续动画，优先只对**采样格中央区域**做节流（该区域本来就是颜色采样区），外围动画照常——这与需求文档 03 节「格线宜细…避开每格中央的颜色采样区」是同一思路的延伸。

## 验收

- 内容静止与 60 Hz 快变两种工况下，`StableDuringExposure` 为真的比例应有数量级差别；
- 相机 30 fps ↔ 投影 60 Hz 时，不再出现"连续多帧错位方式完全相同"；
- 端到端延迟（issue 04 实测值）纳入记录。
