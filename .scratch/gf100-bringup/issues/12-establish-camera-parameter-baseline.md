# 12 建立相机参数基线：把非中性默认值改掉并写入启动流程

规格见 [spec](../spec.md)。

## 问题

卖家提供的 AMCap2 截图暴露了两个**非中性默认值**，它们会直接削弱 `PhotometricProfile` 的模型前提：

| 控件 | 出厂值 | 问题 |
|---|---|---|
| **清晰度(P)** | **80** | 这是锐化（边缘增强）。锐化会在高对比边缘制造**过冲/光晕**，相邻像素亮度不再由 `ρ·(ambient+gain·command)+bias` 解释 → 违反"全图统一 `ambient`/`gain`"假设。而棋盘有细格线、积木有清晰边界，正好全是高对比边缘。 |
| **伽玛(G)** | **300**（即 3.0） | 暗部被大幅压缩。而 `Fit()` 要求投影全黑时桌面仍有 `signal > 1e-4`（`PhotometricProfile.cs:71`），gamma 3.0 会把暗场信号压到接近 0 → 标定直接抛"请提高环境光或曝光"。 |
| 饱和度(S) | 64 | 影响色度通道，需固定；是否中性需实测 |
| 白平衡(W) | 4600 | 需取消自动后固定 |
| 电力线频率 | 50 Hz | ✅ 中国正确，保持 |

## 待做

### 1. 建立"参数基线"常量表

在代码里定义一组固定值（作为标定与运行共同使用的唯一来源），至少覆盖：

```
亮度 0 / 对比度 50 / 饱和度 64（或实测中性值）/ 清晰度 0 / 伽玛 100
白平衡 4600（或实测定标值，自动关闭）
曝光 −6（需换算为实际曝光时间后记录）
增益（实测可调范围后固定）
逆光对比 0 / 低亮度补偿 关闭 / 电力线频率 50Hz
```

其中**清晰度改 0、伽玛改 100** 是本 issue 的主要动作。

### 2. 伽玛与 `ResponseGamma` 必须一致

`PhotometricProfile.ResponseGamma` 默认 2.2、允许 0.1–4。若把相机伽玛设为 100（=1.0，线性），则模型侧 `ResponseGamma` 应设为 **1.0**；若保留其他值，则必须让 `ResponseGamma` 与相机伽玛对应。

**两者不一致时，`Decode`/`Encode` 往返会引入非线性误差**，`TryRecover` 反解出的 reflectance 会系统性偏移。

### 3. 启动时写入（不只记录）

需求文档 01 节要求「相机重连后按记录复核或恢复」。所以要在设备初始化时用 UVC 写接口把这组值**推送到相机**，而不是只写在文档里靠人手动设。

### 4. 复核

- 设完参数后，投影打黑画面，看桌面在相机里的直方图峰值是否 **>1/255 且有细节**；
- 投影打最亮画面，看白桌面是否 **≤250/255**；
- 两项都满足才进入 `PhotometricProfile.Fit`。

## 验收

- 提供"参数基线表 → 实际写入 → 读回校验"的完整记录；
- 用同一场景对比"清晰度 80"与"清晰度 0"两组的 reflectance 分布，证明锐化确实造成了边缘污染；
- 用"伽玛 300"与"伽玛 100"对比暗场信号强度，证明前者会让 `Fit()` 失败。
