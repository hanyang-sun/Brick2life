# 22 电脑接口：USB 数据口、HDMI 第二屏、USB-C 转接验证

规格见 [spec](../spec.md)。

## 问题

需求文档 04 节：

> 优先使用现有 Windows 电脑 1 台，能稳定运行项目所用 Unity 6.3，并**同时接入 UVC 相机与第二显示设备**。预留 **1 个 USB 数据口**和 **1 个 HDMI 视频输出**。若由 USB-C 转接，**先验证该端口确实支持视频输出**，再检查转接后能否保持扩展显示。

本项目对电脑有两个容易被低估的负载：

| 负载 | 说明 |
|---|---|
| UVC 相机持续取流 | 720p MJPEG 60fps + Unity 解码，占 CPU 与 USB 带宽 |
| 第二屏 1080p60 输出 | 投影专用画面，Unity 侧 `Target Display` 指向该屏，**持续渲染** |
| 同时 | 相机取流 + 识别 + 第二屏渲染，三者并发 |

## 待做

1. **确认物理端口**：数清楚有哪些 USB-A/USB-C 口、哪个是独立控制器（避免相机与键鼠/扩展坞抢同一个 root hub）；确认有 HDMI 直出。
2. **若必须走 USB-C 转 HDMI**，逐项验证：
   - 端口旁有 **DP / 闪电图标**，或规格书写「支持 DisplayPort Alt Mode」；
   - `Win + P` 里能选中「**扩展**」（只有"复制/仅第二屏幕"则不行）；
   - 设置 → 系统 → 显示里出现**两个显示器方块**，拖窗口过去两屏内容不同 = 扩展；
   - 分辨率能到 **1920×1080@60**，不退回 1024×768。
3. **排除 DisplayLink**：便宜的多屏方案用 USB 显卡芯片，有压缩延迟，实时投影会卡——必须走 DP 直通（见 issue 23）。
4. **并发压力测试**：相机取流 + Unity 识别 + 第二屏渲染同时跑 10 分钟，记录：
   - CPU/GPU 占用；
   - 相机实收帧率是否掉（与 issue 05 的 T2 对比）；
   - 是否出现丢帧、卡顿、USB 掉线。
5. 相机**先直连电脑**测（不经 Hub），确认基线后再决定是否需要 Hub。

## 风险

- 某些轻薄本的 USB-C 只做「USB 数据 + PD 充电」，**不出视频**。买转接器前必须先确认端口能力，否则买回来只能充电。
- 若相机与第二屏都要用，注意总功耗与 USB 供电能力；必要时给相机走带独立供电的口。
