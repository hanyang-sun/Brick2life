# 06 实测投影横纹与卷帘帧内错位

规格见 [spec](../spec.md)。

## 问题

GF100 是 `Electronic rolling shutter / Frame exposer`（厂商参数表原始写法），逐行读出。720 行在 60 fps 下铺开约 **16.7 ms**，相邻行差约 **23 µs**，首末行差约 16.7 ms。而投影刷新一次也是 **60 Hz = 16.7 ms** —— 两者同量级。

后果分两类，必须分别实测：

- **横纹**：投影/照明 PWM 下，不同行曝光时光照不同 → 横向明暗条纹。会让 `PhotometricProfile` 的"每通道单一 `ambient`/`gain`、全图统一"假设失效。
- **帧内错位**：同一相机帧的最上一行看到投影第 N 帧、最下一行看到第 N+1 帧 → 帧内 `projectorCommand` 不是常量而是一条斜线 → `TryRecover` 必然算错。

这两类的缓解手段不同（横纹可靠长曝光平均掉，错位不能），所以要分开测。

## 待做

### T4 横纹

投影投**纯白**满屏 → 相机对着白纸或空棋盘 → 截帧放大看。

记录：
- 有无条纹；条纹间距（像素）；估计对比度（条纹亮暗行均值差 ÷ 均值）。

若有条纹，把曝光拉长（例如 1/30 s → 1/15 s）后再看，判断是否被平均掉。

### T5 帧内错位（本 issue 的核心）

投影以 **60 Hz 在纯红 / 纯绿之间硬切**（不是渐变），相机拍空板，连续截 20 帧。

判据：
- **每帧整幅同色** → 读出跨度小于投影帧周期，卷帘可用；
- **出现"上半偏红、下半偏绿"** → 帧内跨了两个投影帧，必须走 issue 10 的规避策略，且预期帧可用率打折；
- 记录"整幅同色"的帧数 / 20。

建议记录表：帧号 / 是否整幅同色 / 有无条纹 / 备注。

## 结果如何驱动后续

- 两项**都干净** → issue 08 里卷帘的 `RequiredStableSpan` 可以取 `T_exp`，卷帘几乎无代价。
- **只有横纹** → 靠长曝光 + 50/60 Hz 防闪烁开关消除，issue 08 仍可取 `T_exp`。
- **有帧内错位** → issue 08 必须取 `T_readout + T_row`，issue 10 变成必做，且需评估是否直接换全局快门相机。
