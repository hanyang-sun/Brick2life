# 15 投影过曝与画面均匀性（最亮画面须保留积木顶面颜色细节）

规格见 [spec](../spec.md)。

## 问题

需求文档 02 节（17:32 版新增）明确写：

> **最亮测试画面下应保留积木顶面的颜色细节。**

这条正好对应代码里的两个硬边界：

| 代码位置 | 边界 | 违反后果 |
|---|---|---|
| `PhotometricProfile.cs:11` `ClipLevel = 0.985` | 任一通道 ≥0.985 就算过曝 | 该像素被 `TryRecover` 拒绝（L109） |
| `PhotometricProfile.cs:71` | 投影全黑时 `signal ≤ 1e-4` 抛异常 | `Fit()` 无法完成标定 |

**两头夹击**：投影太亮 → 白桌面过曝；压曝光补救 → 投影黑时又没有信号。

红米 3 Lite 是 180 CVIA。投在 500 × 281 mm（0.1405 m²）上约 **1280 lux**，而室内漫射照明通常 300–500 lux —— **投影仍是主导光源，约为环境光的 3 倍**。所以过曝是真实风险，不是理论风险。

## 另一个隐藏问题：画面不均匀 = 模型失效

`PhotometricProfile` 假设 `ambient`/`gain` 是**每通道一个标量、全图统一**（L63–L77）。投影画面中心亮、四角暗（光学渐晕），会让四角格子的实际光照低于模型预测 → 边角格子误判。

`TryRecover` 里 `r/g/b ∈ [-0.02, 1.05]` 的容差（L116）就是为这种偏差留的，但太大会把错误颜色也放进来。

## 待做

1. **过曝测试**：投影投**最亮测试画面**（全白或最亮游戏帧），相机固定曝光，检查：
   - 白桌面各通道直方图峰值是否 ≤250/255；
   - **积木顶面是否还看得出红/绿的色相**（不是一片白）。
2. **均匀性测试**：投影投**纯灰**（例如 50% 灰），用相机拍整块板，量**中心 vs 四角**的平均亮度差。
   - 判据建议：四角相对中心的差异 **< 15%**；超过则需在标定里做渐晕补偿或在软件里按区域修正。
3. 若过曝：先**降投影亮度**（红米 3 Lite 有节能/影院模式），不要一味压曝光。
4. 记录最终的"投影亮度模式 + 相机曝光/增益"组合，写入参数基线（issue 12）。

## 为什么优先降投影而不是压曝光

压曝光会同时压低"投影全黑"时的环境光信号，可能触发 `signal ≤ 1e-4`。而降投影亮度只影响 `gain·command` 这一项，`ambient` 项由独立照明撑住，模型更容易同时满足两端约束。
